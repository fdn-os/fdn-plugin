# Detailed Plan format

Sole build instruction once sealed.

Normative sections (locked structure §3):

1. Builder context — the four aligned-scope-and-outcomes parts verbatim, the artifact under work as they named it. Do not pin a tool, host, or file format they did not name. When the work is a change: the baseline and what must still work.
2. Build critical path — vertical slices with blockers (each node: outcome, blocked-by, done-check; demoable; sized for this session to land; row map)
3. Requirements checklist — the four parts; each item names the alignment line, evidence mode, and green
4. Acceptance journeys — the sealed User journeys, Primary marked
5. Deploy-like environment
6. How build runs — copy the Loop till green bullets from `modules/build.md` into this section, unshortened. This plan is the path; judgment repairs; no new scope; no spiral. The user is not asked to start accept or to start the next loop. No plan-approve nod; when Plan is green, Build starts in the same flow; stops that show the person are stall, cap 8, a sealed-section change.
7. Challenge record
8. Parked list

Cite the aligned scope and outcomes (`alignment:N`). Do not write a second requirements novel.

No human approve of this plan; Build starts when the Plan loop is green; the person may ask to see the plan at any time, and that is not a gate.
